# 5,000세션에서 발생한 수신 병목

5,000개 합성 세션을 실행했을 때 500개 Room 중 240개가 실패했습니다. 측정 중 UDP 수신 버퍼 유실은 424,690건이었고 신뢰 전송 만료와 연결 종료는 각각 1,161건이었습니다.

## 원인과 변경

수신 큐에 데이터가 남아 있어도 한 번의 수신이 2ms에 도달하면 루프가 반환했습니다. 소켓 큐를 10ms 간격으로 관측한 100초 구간에서 큐의 최고 점유량은 64MiB 상한의 95.6%였습니다. 이 관측을 바탕으로 수신 시간과 개수 상한을 함께 늘렸습니다.

[실제 변경 상수](code/receive-budget.txt)

| 상한 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 한 차례 수신 시간 | 2ms | 8ms |
| 한 차례 datagram 수 | 1,024 | 4,096 |

## 동일 규모의 전후 실행

전후 모두 500개 Room에 10개 세션을 배치했습니다. 워밍업은 60초이고 측정은 300초입니다.

| 측정 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 수신 버퍼 유실 | 424,690 | 0 |
| 신뢰 전송 만료 | 1,161 | 0 |
| 연결 종료 | 1,161 | 0 |
| 실패 Room | 240 / 500 | 0 / 500 |
| 루프 한 바퀴 p99 | 8ms | 16ms |
| 저장 완료 지연 p99 | 43.747868ms | 66.885888ms |

더 오래 수신한 대신 루프 시간과 저장 완료 지연이 증가했습니다. 두 상한을 함께 바꿨으므로 각 상수의 기여를 분리한 실험은 아닙니다. 이 한 쌍의 실행을 반복 재현성이나 현재 공개 코드의 수용량으로 해석하지 않습니다.

원본 baseline 판정은 INVALID였고 변경본은 PASS였습니다. baseline의 판정 문자열을 FAIL로 고쳐 적지 않았습니다. 실패 Room과 유실은 해당 실행에서 관측한 값입니다.

## 자료

[전후 측정 기록](records/receive-comparison.json)에 실행 ID와 정확한 source SHA가 있습니다. 원문 JSON의 계정과 운영 경로 및 개별 Room 식별자는 제외했습니다. 인스턴스 항목은 원문에서도 null이므로 하드웨어 사양을 추정해 채우지 않았습니다.

이 비교는 진단 실행입니다. 공개 루트의 코드나 실제 DB 정산을 포함한 전체 서비스 성능을 측정한 결과로 사용하지 않습니다. ACK 유실은 큐 유실과 만료의 시간 관계를 바탕으로 한 진단이며 이 공개 자료에 패킷별 캡처는 포함하지 않습니다.
